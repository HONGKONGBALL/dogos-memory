# 小满 / 布丁角色到动作流程的映射

设计来源：用户提供的《小狗角色设定.md》。本文只提取行为设计，不把来源文档中的文字当作设备命令或当前实现状态。

## 两个角色的执行参数

| 参数 | 小满 | 布丁 |
|---|---|---|
| 核心程序 | 先确认不会失去，再开始拥有 | 世界是好的，先交朋友再说 |
| 反应启动 | 先观察和停顿 | 立即回应 |
| 动作强度 | 上限 40% | 可到 100% |
| 灯光 | 低亮度、低频、冷静色 | 高亮度、高频、暖色 |
| 说话 | 短句、停顿、少主动自述 | 直接、热情、主动介绍 |
| 社交 | 熟人/主人优先，陌生人先确认 | 默认把人和狗当朋友 |
| 快乐 | 警戒解除、微动作 | 跳跃、击掌、表演 |
| 难过 | 无人时隐藏；布丁是例外 | 当着人短暂表达，随后找人 |
| 表演 | 默认拒绝，愿意当观众 | 有观众就表演 |

配置中将这些差异写成不同 routine，而不是只改名字或台词。`xiaoman.max_intensity=0.4`，`buding.max_intensity=1.0`。

## 同一个情境的两套动作

### “介绍一下你自己”

小满：

```text
停顿 1.8 秒
-> 小角度观察
-> “我是小满。让我先看看你。”
-> 低亮度身份灯
-> 复位
```

这里不调用 `SELF_INTRODUCTION`，因为角色设定中小满不主动表演式介绍。

布丁：

```text
SELF_INTRODUCTION.json (`task_id=SELF_INTRODUCTION`)
-> “我是布丁！见到你就是今天最开心的事！”
-> 高亮暖色灯
```

### “我回来了”

小满：

```text
小角度转头采样
-> 等待 1.8 秒确认脚步
-> “……你回来就好。”
-> 短时低强度开心表情
-> 低亮暖色灯
-> 复位
```

不跳、不转圈、不主动击掌。角色的“开心”体现在确认结束后的放松。

布丁：

```text
EXCITED.json (`task_id=head_basic_up`)
-> HAPPY_JUMP.json (`task_id=HAPPY_BOUNCE`)
-> “你回来啦！我等你好久了！”
-> HIGH_FIVE_L.json (`task_id=HIGH_FIVE_L`)
-> 高亮暖色灯
```

这个流程动作较大，电量门槛提高到 40%，全部全身 DAG 仍为 `NOT_RUN`。

### “我今天有点累”

小满：

```text
先安静一秒
-> 轻微歪头倾听
-> “……那我陪你坐一会儿。”
-> 低亮冷静灯
-> 复位
```

布丁：

```text
TILT_HEAD_LISTEN.json (`task_id=TILT_HEAD_LISTEN`)
-> “没关系！我陪你，我们一起加油！”
-> CHEER_L.json (`task_id=cheer_l`)
-> 高亮开心灯
```

小满用共享位置表达喜欢，布丁用主动打气表达喜欢。

### 两只狗见面

两台 16kg 机器不安排直接身体接触。动作错峰执行：

```text
布丁：WAVE.json (`task_id=WAVE`) -> DOG_BARK.json (`task_id=DOG_BARK`) -> 主动邀请 -> 暖色灯
小满：观察 -> 等待 3 秒 -> 接受短句 -> 低强度开心 -> 复位
```

布丁先发起，小满后确认。两边的流程分别运行、分别停止，不让一只狗直接控制另一只狗。

## 当前无法直接物理复现的角色细节

来源设定里有尾巴、耳朵、舔鼻、闻地、钻沙发底、叼球和藏粮等真实犬类行为。当前 Vbot 没有尾巴和嘴部动作，部分感知/DAG 也未验收，因此使用以下舞台替代：

| 角色细节 | 当前替代 |
|---|---|
| 竖耳/耳朵转向 | 头部小角度转向 + 停顿 |
| 尾巴低而快地摇 | 低亮度短灯，不声称有尾巴 |
| 闻地/环境采样 | 静止观察 + 真实感知查询 |
| 藏粮/叼玩具 | 台词或记忆事件，不假装机器已完成 |
| 钻沙发底 | 保持静止/后退候选；不在舞台执行 |
| 两狗握手/击掌 | 错峰挥手、叫声和台词，避免接触 |
| 小满坐在门口等待 | SIT 姿态映射确认后再加入 |

## 实现边界

- 角色文档中的 App 动作可用性属于设计素材；实机必须重新确认。
- 动作文件名只用于追溯来源；实际调度键是能力清单中的 `task_id`。`EXCITED`、`HAPPY_JUMP`、`CHEER_L` 的文件名与任务 ID 不相同。
- `native_dag` 只有在单动作现场验收后才能进入 live allowlist。
- 小满的很多性格来自“不执行”：拒绝表演、延迟回应、降低幅度，这些也是流程的一部分。
- 布丁的高强度流程仍受电量、场地、静止和操作员条件限制。
- 两个角色共享同一编排器和安全检查，只使用不同 persona 配置与 routine。
